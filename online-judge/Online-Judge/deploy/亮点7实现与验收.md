# 亮点7实现与验收记录

本文件记录亮点7首版本地实现与验收证据，范围为 Windows Docker Desktop、Java 8、单后端实例。所有结论限定于下面实际执行的测试。

## 部署

1. 在项目专用 MySQL 8 数据库执行 `sql/007-sandbox-resource.sql`。
2. 后端根目录执行 `docker build --network=none -t oj-sandbox-runtime:7 sandbox-runtime`。
3. 使用现有项目本地配置启动 Judge；Docker Desktop 使用 Linux 容器及 cgroup v2。

新增 `sandbox.runtime.image` 默认 `oj-sandbox-runtime:7`，`sandbox.runtime.memory-bytes` 默认805306368；外层内存与 swap 总额相等。正常容量 N 使用 `judge.task.concurrency`，回收余量使用 `sandbox.docker.pool.recovery-reserve`（默认2），总额度 H=N+余量。补池扫描 `sandbox.docker.pool.replenish-ms` 默认2000。

执行器当前硬限额：源码262144字节、128例、输入每例16384字节、stdout/stderr各65536字节、运行内存16～256MiB、CPU每例1～60000毫秒；编译任务组256MiB、CPU30秒。用例墙钟保护为CPU预算的5倍加2秒。数值用于本机验证，尚不能作为性能承诺。

## 已实现并分项测试

- 持久身份与容量预留；数据库锁保护并发计账；附属资源未回收及创建未知保留额度。
- 预热一次性容器、持久独占领取、用后销毁、补池与回收分开调度、旧代次回收。
- Java 8可信管理器与独立监督进程；项目专属cgroup子树；先分组再降权。
- Docker attach持续连接、分配前检查帧长、有限队列和输出缓冲。
- 编译一次、逐用例任务组和JVM、整组终止与文件清理验证。
- CPU限额、输出限额、任务组内核OOM证据；固定判定优先级、跨例首次失败。
- 答案只归一化换行并忽略末尾换行，保留其他空白。
- 阶段清理确认随协议传回并写入结果；未确认清理不能判成功，已确认 CE/RE/超限结果不被回收故障覆盖。
- 运行期间总预算到期及监督循环异常通过本容器专属 `cgroup.kill` 终止。真实测试曾复现容器内对 PID1 发信号无效，已修复并通过包含原6项的8项执行器回归。
- 独立维护调度线程允许慢回收期间继续补池与扫描，配置测试已通过。
- 正式 HTTP 受理至落库链路的 AC/WA/CE/RE/TLE/OLE/MLE 在此前运行中已通过；代码变更后仍须整体重跑。
- 固定镜像内容 ID 和 JDK 版本已随资源身份落库，真实 Docker 测试已验证。
- 创建操作分阶段持久记录：未发起外部操作的预留可回收；已确认子树但尚未请求 Docker 的中断可回收；真实未知请求继续占额度。对应环境及子树集成测试已通过。
- 子树回收失败时，容器、目录及连接完成证据分别保存；真实测试验证残留占满 H、重启不补建、确认回收后恢复。
- 监督器硬退出、控制连接断开有独立守护；平台终止先写受保护故障标记，防止整组终止竞争误报 RE。各故障注入测试已通过。
- 输入经 argv 进入固定启动命令，特殊字符不参与 shell 解析；真实测试已通过。
- 可写区具有字节及 inode 上限；文件数量耗尽和用户进程数耗尽后清理及后例执行测试已通过。用户有效 UID 和零 capabilities 已验证。
- 阶段准备、墙钟、CPU 与清理耗时通过协议返回并保存；就绪前验证控制器、禁止 swap、降权和管理目录保护。

- `SandboxReuseBenchmarkTest`：通过。三轮交错比较，双方源码和 JDK 相同、编译一次、六个独立 JVM；每例验证输出。数据见 `亮点7性能对照.csv`。
- 提交内复用耗时4795、4606、4010毫秒；每例新容器耗时13547、13034、13403毫秒。计时包含环境创建、自检、运行与回收；复用组还包含逐例清理验证。基线包含独立编译环境及有界产物传输，通过等待用例保持编译环境存活，因此另含该等待 JVM 的启动开销。该小样本仅说明本机该工作负载的结果，不作为生产吞吐承诺。
- `JudgeSubmissionHttpIntegrationTest` 三项通过：七类判定全部一次执行后完成；并发同键受理与权限隔离；题目变更后的旧快照重放及完成任务禁止重试。阶段证据通过实际 HTTP 返回并持久化。
- Judge JAR 实际启动成功，监听8081，完成上述真实 RabbitMQ、MySQL、Redis、Elasticsearch 链路。鉴权/冲突测试产生的预期业务拒绝不能作为服务启动错误；数据库原有故障注入历史保留。
- 新增编译产物超过1024个的真实测试通过，返回 CE 所需编译失败证据，不进入用例，不误作系统重试。
- 最后更新执行器镜像后，完整16项执行器测试通过；重启 Judge 清退旧代预热资源后，七类 HTTP 判定再次全部通过（`target/highlight7-http-final.log`）。Judge 保持监听8081。

## 参数与运行边界

默认正常并发 N=1、回收余量 R=2；并发隔离另验证两份真实环境各执行6例十万整数排序，资源预留验证16次并发竞争及 H 耗尽恢复。未测量更高并发的稳定吞吐，不据此提高默认并发。CPU 包含 JVM 开销，墙钟采用5倍CPU预算加2秒，不扣固定 JVM 基线。

源码、协议、输出、任务组进程及可写区字节/inode均有界。Docker/API结果未知仍保留额度，允许暂停受理而不突破 H；宿主或 Docker 整体失效不能承诺准点终止。只维护项目专属资源，不修改全局交换或 Docker 配置。
